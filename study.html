Exam technique

How to answer each section

Every good answer has the same shape: name the concept → explain it with the numbers or code you were given → say what to do and why.

Section 1Workflow & methodology 5 marks

Write 2–3 short paragraphs:

  1. Problem: name the mistake in the story.
  2. Why it is a problem: use the numbers in the story.
  3. Fix: what to do instead.

If they ask for the first step, it is Problem Definition (framing the problem), step 1 of the course workflow. Know the 9 steps in order: Problem Definition → Data Collection → EDA → Data Preparation → Feature Engineering → Model Training → Model Evaluation → Hyperparameter Tuning → Deployment & Monitoring.

Check the story against this list. Most questions hide 2 or 3 of these mistakes:

Mistake in the storyName itFix
Starts training before defining the goal or metricNo problem framingDefine the objective with stakeholders, the task type and the metric first
Reports high accuracy on rare positives (e.g. 6% sick)Accuracy trap / imbalanced dataCompare with a baseline; use recall, precision, F1 and the confusion matrix
Scales or imputes the whole dataset, then splitsData leakageSplit first; put preprocessing in a Pipeline fitted on training data
Tunes or picks the model with the test setTest set leakage, optimistic scoreTune with cross-validation on training data; use the test set once
Picks the model with the best training scoreOverfitting not detectedChoose by validation / cross-validation score
Train 100%, test 78%Overfitting (high variance)Regularize (max_depth, alpha, early stopping), more data, ensemble
Train and test both lowUnderfitting (high bias)More complex model, better features, less regularization

Answer shape. "The first step is to frame the problem: … The main problem is [name], because [why, using the numbers in the story]. To fix it, [action]. Then [next correct step], and finally evaluate once on the test set."

Section 2Python code interpretation 5 marks

  1. Purpose of the whole snippet in one sentence ("this code tunes a decision tree with cross-validation").
  2. Each line / function: what it does (fit learns, predict gives labels, predict_proba gives probabilities…).
  3. Each parameter: what it controls and why this value (test_size=0.2 → 20% test; random_state=42 → reproducible).
  4. The concept behind it: leakage, overfitting, reproducibility, class balance, variance, bias.
  5. What you expect as output, or what would go wrong without it.

The code cheat sheet lists what to say for every function used in class.

Section 3Model output & interpretation 4 marks

  1. Quote the numbers ("recall for malignant is 0.93, so 3 of 42 cancers are missed").
  2. Compare: class vs class, model vs model, train vs test, CV vs test.
  3. Explain why: class imbalance, overfitting, variance, a linear vs non-linear model, a small test set.
  4. Decide in context: in a hospital, missing a sick patient (false negative) is usually the worst error, so prefer recall.

ReadA classification report

  • precision (per class): of the cases predicted as this class, how many were right.
  • recall (per class): of the cases that really are this class, how many the model found.
  • f1-score: one number that balances precision and recall.
  • support: how many test cases of each class exist. Few cases = less reliable numbers.
  • macro avg: simple average over classes (each class counts the same). weighted avg: weighted by support, so it leans toward the bigger class.
  • The class with the higher f1 is the class the model predicts best. Here benign (0.97) > malignant (0.95), because there are more benign examples (imbalance) and borderline malignant tumours are harder.

ReadA confusion matrix (Scikit-Learn)

predicted benignpredicted malignant
actual benign71TN · correct1FP · false alarm
actual malignant3FN · missed cancer39TP · cancer found

Rows = actual, columns = predicted. The diagonal is correct. Everything off the diagonal is an error. The error type matters more than the total: here the model makes 4 errors, and 3 of them are missed cancers.

Other outputs you may get.
  • Train vs test accuracy: a big gap = overfitting; both low = underfitting.
  • CV mean ± std: the mean is the expected performance; a big std means the model is unstable across folds.
  • OOB score: a built-in validation estimate for bagging and Random Forests. It should be close to the test score.
  • Best CV score vs test score: the test score is the honest one to report. The best CV score is a little optimistic because it is the maximum of many tries.
  • Feature importances: what the model relies on. Association, not causation.

Module 1 · foundations

The machine learning landscape

Traditional programming: data + rules → output. Machine learning: data + desired outputs → learning algorithm → model. A good model does not memorize; it generalizes to new data.

1.1Key words

TermMeaningIris example (class demo)
Feature (X)An input variablepetal length, petal width…
Label / target (y)The answer we want to predictthe species
ModelThe learned relationshipa decision tree
TrainingAdjusting the model with examples (fit)tree.fit(X_train, y_train)
PredictionUsing the model on new input (predict)tree.predict(X_test)
GeneralizationDoing well on unseen datathe test accuracy
Parameter vs hyperparameterLearned from data (coefficients) vs chosen by you before training (max_depth)max_depth=3 is a hyperparameter

Mitchell's definition: a program learns from experience E on a task T if its performance P improves with E. (Spam filter: T = classify emails, E = labelled emails, P = accuracy.)

1.2Types of learning

TypeIdeaExample
SupervisedExamples come with the answer. Classification predicts a category, regression a number.Spam or not; house price
UnsupervisedNo answers; find structure such as groupsKMeans clusters on Iris without using y
ReinforcementAn agent learns from rewards and penaltiesA game-playing agent
Batch vs onlineTrain on all data at once (offline) vs learn continuously from new dataMonthly retraining vs a live stock model
Instance-based vs model-basedCompare new cases with stored examples (KNN) vs build a model that captures the pattern (linear regression)KNN vs linear regression

1.3Main challenges

  • Poor-quality data: missing values, noise, errors. A complex algorithm cannot fix bad data.
  • Nonrepresentative data: the training data does not look like the real world (sampling bias, historical bias, small samples).
  • Overfitting: learns the training data too closely, including noise. Great on training, poor on new data.
  • Underfitting: too simple to capture the pattern. Poor on both.

1.4Code from class (Module 1 demo)

  • The test set is kept aside to estimate generalization; "do not repeatedly use the test set to choose the model".
  • max_depth controls how complex the tree can become.
  • Accuracy gives one number; the confusion matrix shows which classes are confused.

Check yourself

99% training accuracy, 71% on new data from the same population. Diagnosis?

Overfitting. The model memorized the training data.

Both training and validation errors are high and close. What helps?

A more complex model or better features (underfitting). More data of the same kind will not help.

Module 2

End-to-end machine learning workflow

The course workflow (Figure 2.1) has 9 steps: define the problem, collect data, explore it, prepare it, engineer features, train, evaluate, tune hyperparameters, then deploy and monitor. It is a loop: feedback and new data send you back to improve.

1 · Problem DefinitionDefine the business problem and objectives
→
2 · Data CollectionGather relevant data from various sources
→
3 · Exploratory Data Analysis (EDA)Explore and visualize data to understand patterns and relationships
→
4 · Data PreparationClean, transform and prepare data for modeling
→
5 · Feature EngineeringCreate and select relevant features to improve performance
→
6 · Model TrainingTrain machine learning models using training data
→
7 · Model EvaluationEvaluate performance using appropriate metrics
→
8 · Hyperparameter TuningOptimize hyperparameters to improve performance
→
9 · Deployment & MonitoringDeploy the model and monitor it in the real world

↺ Iterate and improve based on feedback and new data. Memory trick, in order: Define → Collect → Explore → Prepare → Engineer → Train → Evaluate → Tune → Deploy.

Where does the train/test split go? It is not a box in the figure: Cascade covers it under Model Training & Evaluation. In code, though, the Module 2 demo says "Split the data before learning transformations": split right after exploring and before any step that learns from the data (imputing, scaling, selecting features). Otherwise you get data leakage.

Step 1Problem Definition (always the first step)

  • Business problem and objectives: what decision will the prediction support? Who are the stakeholders? What are the constraints? Many projects fail from unclear objectives or the wrong problem, not from bad algorithms.
  • Problem type: classification (category: spam, churn), regression (number: house price, sales) or clustering (groups without labels).
  • Performance measure: chosen from the cost of errors. Demo questions: "Who uses the predictions? What is the cost of overestimating or underestimating? Which errors matter most?"
MetricQuestion it answersUse it when
AccuracyWhat share of all predictions is correct?Classes are balanced. Misleading with rare positives.
PrecisionWhen the model says "positive", how often is it right?False positives are costly (spam filter, expensive investigation).
RecallOf the real positives, how many did it find?False negatives are costly (disease, fraud).
F1Balance of precision and recallYou need both, or the data are imbalanced.
MAEAverage absolute error, in the target's unitsRegression; easy to explain.
RMSELike MAE, but big errors count much moreRegression where large errors are especially bad.

Module 2 demo / Activity Core Task 1. actual = [1,1,1,1,0,0,0,0], predicted = [1,1,0,1,1,0,0,0]. Position by position: TP = 3, FN = 1 (the third case), FP = 1 (the fifth), TN = 3. Accuracy, precision, recall and F1 are all 0.75.

Step 2Data Collection

Gather relevant data from the available sources (databases, files, sensors). Check, using Module 1's challenges, that the data are:

  • Representative of the real situation where the model will be used (no sampling or historical bias, enough examples).
  • Good quality: data merged from several sources can be inconsistent, and sensors add measurement errors and noise.
  • Available at prediction time: a column you will not have when predicting cannot be used (that is leakage).

Step 3Exploratory Data Analysis (EDA)

"What does the data look like? Are there missing values, outliers or important relationships?" EDA uses summary statistics, distribution analysis and correlation analysis.

  • Plots: histograms (distribution, skew, outliers), box plots (extreme values), scatter plots (relationships, clusters), correlation heatmaps (many variables at once).
  • Know the data types: numerical, categorical, ordinal, text. They decide the preprocessing.
  • Correlation (−1 to +1) shows linear relationships, useful predictors and redundant features. It is not causation and can miss non-linear patterns.

Step 4Data Preparation

IssueWhat to do
Missing valuesRemove rows (loses information) or impute with the mean or median (adds assumptions; the median is robust to outliers).
OutliersInvestigate before deleting. Demo: Age = 190 may be a typing error, but automatic deletion can remove rare valid cases.
DuplicatesIdentify and remove them (df.duplicated().sum()) to avoid biased results.
Categorical variablesLabel encoding (a number per category) only for ordered categories (low/medium/high). One-hot encoding (one 0/1 column per category) for nominal ones (colour, country), so the model doesn't invent a false order.
Feature scalingNormalization (MinMaxScaler) → range 0–1. Standardization (StandardScaler) → mean 0, std 1. Needed for distance and gradient models (KNN, linear/logistic regression, SVM), not for trees.

handle_unknown="ignore": a category never seen in training becomes all zeros instead of crashing.

In practice, these steps run inside a pipeline fitted on the training data only (after the split):

  • Data leakage = information from the test set (or the future) gets into training, so the score looks better than reality. Fitting the imputer or scaler on all the data is leakage.
  • fit_transform on train learns the statistics and applies them; transform on test only applies them.
  • ColumnTransformer: different preprocessing for different columns (a numeric pipeline and a categorical pipeline).

Step 5Feature Engineering

Creating, selecting and transforming variables. Well-designed features often matter more than the choice of algorithm.

  • Feature creation: new variables from existing ones. Demo: RoomsPerHousehold = AveRooms / AveOccup, BedroomsPerRoom = AveBedrms / AveRooms. Never use future or target information, and create them the same way for future data.
  • Feature selection: keep the informative variables and remove irrelevant or redundant ones → better performance, less complexity, faster training, easier interpretation, less overfitting.
  • Transformation pipelines: chain imputation, encoding, scaling and feature engineering so they are applied automatically and the same way every time (reproducibility, automation, data integrity, no leakage).

Does adding a feature always help? No: an irrelevant or leakage-prone feature can make the model worse, or give an unrealistically optimistic score.

Step 6Model Training

  • Train on the training data only (80/20 or 70/30 split).
  • Start with a baseline (the mean for regression, the majority class for classification) as a reference point: "how much value does ML add?"
  • Training RMSE alone is not enough: a flexible forest can memorize, so its training error looks great.

Step 7Model Evaluation

  • Compare models with metrics that fit the problem (accuracy, precision, recall, F1, RMSE, MAE), looking for the best balance of performance, efficiency, interpretability and generalization.
  • k-fold cross-validation: split the training data into k folds; train on k−1, validate on 1, k times. The mean is more reliable than one split; the std shows stability.
  • Scikit-Learn maximizes scores, so error metrics come out negative (neg_…). Put a minus sign back.
  • The test set gives the final unbiased estimate on unseen data. Use it once, at the end, not for repeated tuning.

Step 8Hyperparameter Tuning

  • Hyperparameters are set before training (max depth, number of trees, regularization strength). Parameters are learned from the data (coefficients).
  • Grid Search tries every combination with cross-validation (finds the best of the grid, but expensive). Randomized Search samples random combinations from ranges (faster for large spaces, near-optimal).
  • model__n_estimators: in a pipeline, the parameter name is step name + two underscores + parameter.
  • best_params_ = best combination, best_score_ = its mean CV score, best_estimator_ = the model refitted on all the training data, then evaluated once on the test set.

Step 9Deployment & Monitoring

A model is not finished when a score is printed. Before and after deploying, ask (Module 2 demo): Is the data available at prediction time? Is performance acceptable for important groups? What happens when the data distribution changes (drift)? How will predictions and errors be monitored? Can the whole pipeline be reproduced? Can stakeholders understand the output? Then go back around the loop with the feedback and new data.

Exam traps.
  • The first step is Problem Definition (framing), not data collection, EDA or training.
  • In the course order, Model Evaluation (7) comes before Hyperparameter Tuning (8), and Feature Engineering (5) after Data Preparation (4).
  • Split before imputing, scaling or selecting features with the data.
  • The test set is not for tuning. Tune with CV; test once.
  • Correlation is not causation. A feature can also hurt if it is irrelevant or leaks the answer.
  • Trees don't need scaling; KNN and gradient-based models do.

Check yourself

Why is fitting the scaler on the whole dataset a leakage risk?

The scaler learns the mean and std from test rows too, so test information shapes training and the score is optimistic.

What did the baseline teach us?

The minimum score any useful model must beat. If a model barely beats "predict the mean", it adds little value.

Why do RMSE scores come out negative in cross_val_score?

Scikit-Learn treats higher scores as better, so it returns negative errors. Multiply by −1.

Module 3

Classification

Judge a classifier by the kind of mistakes it makes. Define the positive class, read the confusion matrix, then pick the metric and threshold that match the cost of each error.

3.1Problem types

TypeMeaningExample
BinaryTwo classesbenign / malignant
MulticlassOne label from 3+ classesdigits 0–9, Iris species
MultilabelSeveral labels at once for one examplea photo with a dog, a bicycle and a person
MultioutputSeveral target variables predicted together, each with its own classessecurity status + fire risk; image denoising

For multiclass with binary-only algorithms: One-vs-Rest trains one classifier per class against all others; One-vs-One trains one per pair of classes. Trees, Random Forests, KNN and Naive Bayes handle multiclass directly.

3.2The breast-cancer demo (the class's main example)

  • The target is recoded so 1 = malignant: the positive class should be the event we want to detect.
  • stratify=y keeps the benign/malignant ratio the same in train and test.
  • Scaling is in the LR and KNN pipelines (distances and weights depend on scale) but not for the Random Forest (trees split on thresholds).
  • Same data, three ways of learning: LR learns a linear boundary, KNN looks at nearby examples, RF combines many trees. That is why their predictions differ.

Reading it. LR and RF have the same accuracy but make different errors. RF has perfect precision (no false alarms) but misses 4 cancers; LR misses 3 and has the best recall, F1 and AUC. For cancer screening, choose LR. "The best model depends on the metric and the application, not accuracy alone."

3.3Confusion-matrix metrics

  • Precision = TP / (TP + FP): correctness of positive predictions.
  • Recall (sensitivity, true positive rate) = TP / (TP + FN): share of real positives found.
  • Specificity (true negative rate) = TN / (TN + FP): share of real negatives found. LR: 71/72 = 0.986.
  • False positive rate = FP / (FP + TN) = 1 − specificity.

3.4The accuracy trap

A model that always says "negative" gets 94% accuracy and finds zero positives. Always compare with a baseline and look at recall.

3.5Thresholds: precision vs recall trade-off

  • Lower threshold → more cases called positive → recall ↑, precision usually ↓.
  • Higher threshold → stricter → precision ↑, recall ↓.
  • For screening, 0.30 is better (fewer missed cancers). Choose the threshold on validation data, not the test set.

3.6ROC curve, AUC and PR curve

  • ROC curve: recall (TPR) vs false positive rate across all thresholds.
  • AUC: area under ROC, 0 to 1. Close to 1 = excellent at ranking positives above negatives; 0.5 = random guessing. Above 0.90 is excellent.
  • Use ROC when classes are fairly balanced; use the precision-recall curve when the positive class is rare and finding it matters.

3.7Stratified cross-validation and tuning

  • StratifiedKFold keeps the class ratio in every fold; shuffle=True mixes rows first.
  • cross_validate can return several metrics at once (cross_val_score returns one).
  • Preprocessing must stay inside the pipeline so each fold learns its scaling only from its own training part.
  • CV results in class: LR recall 0.953 ± 0.040, KNN 0.929 ± 0.024, RF 0.929 ± 0.044. The ± is the fold-to-fold variation.

3.8Multiclass and error analysis

Digits demo: accuracy 0.972, but classes 1 and 8 have only 0.89 precision and recall. The confusion matrix shows which classes are confused (similar shapes).

Causes of errors: poor data quality, class imbalance, overlapping classes, insufficient features, overfitting. Fixes: more data, better features, balance classes, tune hyperparameters, another algorithm, inspect the errors by hand. In the LR demo, two of the four errors were borderline (malignant probability 0.49 and 0.51, right at the threshold), one was 0.31, and one was confidently wrong (0.06): that last one deserves a manual look.

Exam traps.
  • Precision looks at predicted positives; recall looks at actual positives.
  • Rows of the Scikit-Learn confusion matrix are actual; columns are predicted.
  • Same accuracy ≠ same model. Compare the error types.
  • Lowering the threshold raises recall, not precision.
  • PR curve for rare positives; ROC for balanced classes.

Check yourself

In disease screening, which matters more: precision or recall?

Recall, because a false negative (a missed sick patient) is the most costly error.

Why can scaling matter for KNN?

KNN uses distances, so a feature with large numbers (income) would dominate one with small numbers (age).

Why can different algorithms give different predictions on the same data?

They learn different decision boundaries (linear, neighbour-based, tree-based) and have different hyperparameters.

Module 4 · focus

Training models

Training = finding the parameters that make the cost (error) smallest. Gradient descent gets there step by step. Polynomial features add flexibility; regularization and early stopping stop that flexibility from overfitting. Logistic regression uses the same idea to output probabilities.

4.1Linear regression

  • Prediction = intercept + coefficient × feature (simple), or + one coefficient per feature (multiple).
  • Coefficient: how much the prediction changes when that feature increases by 1 and the others stay the same. Positive → goes up together; negative → inverse; bigger magnitude → stronger. Compare magnitudes only if the features are scaled.
  • Residual = actual − predicted. Small residuals = good fit.

Computational complexity grows with the number of samples, the number of features and the algorithm (a direct solution vs iterative optimization). For very large data, gradient descent scales better.

4.2Gradient descent

The cost for linear regression is the MSE. Gradient descent starts from random parameters and repeatedly takes a step downhill: opposite to the gradient (the direction where the cost grows fastest).

Learning rate (Module 4 lab)What happens
0.02 (too small)Slow convergence: many tiny steps
0.1 (good)Fast and stable
0.8 (too large)Overshoots the minimum: unstable, can diverge
VariantData per updateGoodBad

Scale the features before gradient descent; otherwise one learning rate cannot suit features with very different ranges.

4.3Polynomial regression

  • PolynomialFeatures adds x², x³… so a linear model can draw a curve (it stays linear in its parameters).
  • include_bias=False: skip the column of 1s, because LinearRegression already fits an intercept.

4.4Learning curves

PatternWhat you seeWhat to do

4.5Regularization: Ridge, Lasso, early stopping

Regularization adds a penalty on large coefficients to the cost, so the model stays simpler and generalizes better. alpha = penalty strength (0 = plain linear regression; bigger = more shrinking, more bias, less variance). Scale the features first.

RidgeLasso
PenaltyL2L1
EffectShrinks all coefficients toward 0; keeps every featureCan set some coefficients exactly to 0
UseMany useful, correlated featuresAutomatic feature selection, simpler model

Early stopping: stop training when the validation error is at its minimum; after that point it rises while training error keeps falling (overfitting).

  • max_iter=1: each fit runs one epoch. tol=None: don't stop on its own.
  • warm_start=True: continue from the previous weights instead of starting over.
  • The data are scaled (StandardScaler fitted on train only) because SGD is sensitive to scale.

4.6Logistic regression (a classifier, despite the name)

  • Computes a linear score, then the sigmoid squeezes it into a probability between 0 and 1.
  • Decision threshold (default 0.5) turns the probability into a class. Where the class changes is the decision boundary (a straight line/plane).
  • Fast, gives interpretable probabilities, a strong baseline for binary problems (disease, spam, fraud, purchase).

Two settings you may see: C is the inverse of regularization strength (smaller C = stronger penalty, simpler model); class_weight="balanced" gives the rare class more weight, which usually raises its recall.

Exam traps.
  • Lower training error does not mean a better model. Decide with validation error.
  • Lasso removes features; Ridge only shrinks them.
  • Too large a learning rate diverges; too small is slow. Scale the features.
  • Logistic regression is classification. Its output is a probability; the threshold makes the label.
  • Underfitting: more data won't help. Overfitting: more data can help.

Check yourself

Validation error starts rising while training error keeps falling. What is happening and what do you do?

The model is starting to overfit. Stop at the epoch with the lowest validation error (early stopping).

Why does PolynomialFeatures use include_bias=False before LinearRegression?

LinearRegression already fits the intercept, so a column of 1s would be redundant.

Which model gives automatic feature selection?

Lasso (L1), because it can set coefficients exactly to zero.

Module 5 · focus

Decision trees

A tree asks a series of yes/no questions about the features. CART chooses each question greedily to make the groups purer. Without limits it memorizes the data, so max_depth and the minimum-sample settings are its regularization.

5.1Structure

PartWhat it is
Root nodeAll the training data; holds the first split
Internal nodeApplies a rule to one feature; True goes left, False goes right
Leaf nodeNo more splits; gives the prediction (majority class, or average value for regression)
Decision ruleFeature vs threshold, e.g. petal length <= 2.45, "Income > $60,000?"

Splitting again and again is recursive partitioning, until a stopping rule (max depth, min samples, pure node). Big strength: interpretability; you can trace every prediction from root to leaf (useful in healthcare, finance, risk).

5.2Reading a node in plot_tree

value = [50, 0, 0] is pure (only class 1). value = [3, 25, 22] is mixed.

5.3Gini impurity and entropy

  • Both measure how mixed a node is. Pure node = 0. CART picks the split with the biggest drop in impurity.
  • Gini: chance of misclassifying a random item. Default in Scikit-Learn, slightly faster.
  • Entropy: uncertainty (information theory).
  • They usually give very similar trees. Demo (Iris, depth 3): both had test accuracy 0.895, depth 3, 5 leaves.

5.4CART (how the tree is built)

  1. Evaluate candidate splits (every feature and threshold).
  2. Measure the impurity of the resulting groups.
  3. Choose the split with the greatest impurity reduction.
  4. Partition the data, then repeat for each child (recursively).
  5. Stop when a criterion is met (max depth, too few samples, pure nodes).

Greedy: the best split right now, not the best possible tree overall (fast, works well, not guaranteed optimal). Binary: every node has exactly two branches.

Complexity: training is costly (many candidate splits; grows with samples, features and depth). Prediction is very cheap: one path from root to leaf.

5.5predict vs predict_proba

Leaf value = [0, 2, 43] → predicts virginica with probability 43/45 ≈ 96%. A balanced leaf like [0.20, 0.80] means less confidence (80% for the second class).

5.7Tuning with GridSearchCV (demo + in-class activity)

  • Test (0.895) < CV (0.938): the best CV score is a bit optimistic, and the Iris test set is small (38 flowers: one error ≈ 2.6 points). Report the test score.
  • Many combinations tied at 0.938, so prefer the simplest tree.
  • CV is more reliable than choosing by training accuracy, which always favours the deepest tree.

  • 100% training accuracy is a warning sign, not a success.
  • Gini and entropy rarely change the result much; depth does.
  • CART is greedy and binary, so it is not guaranteed to find the globally best tree.

Check yourself

The in-class activity asks: why is the highest training accuracy not automatically the best choice?

An unrestricted tree reaches 100% on training by memorizing noise; what matters is accuracy on unseen data (CV or test).

Are tree decision boundaries smooth, diagonal or axis-aligned?

Axis-aligned, because each rule compares one feature with a threshold.

What does a leaf with probabilities [0.20, 0.80] mean?

80% of the training rows in that leaf belong to the second class, so the tree predicts it with 80% confidence.

Module 6 · focus

Ensemble learning & Random Forests

One tree is unstable (high variance). Many diverse models make different errors that cancel out. Bagging-type methods train independent trees to cut variance; boosting trains learners one after another to cut bias; voting and stacking combine different algorithms.

6.1Voting classifiers

  • Hard voting: each model votes a label, majority wins (A, A, B, A → A).
  • Soft voting: average the predicted probabilities, so confident models count more. Every model needs predict_proba, so the demo uses SVC(probability=True).
  • Works best with diverse and reasonably accurate base models (LR + tree + SVM/KNN).

Here the ensemble did not beat logistic regression: an ensemble is not automatically better.

6.2Bagging, pasting and OOB

  • Bagging (bootstrap aggregating): each model trains on a random sample drawn with replacement (rows can repeat). Pasting: without replacement.
  • Same algorithm, different data subsets, trained independently (in parallel); combine by majority vote (classification) or average (regression).
  • Main goal: reduce variance and overfitting of high-variance models like deep trees.
  • OOB (out-of-bag): each bootstrap sample holds about 63.2% of the rows; the other 36.8% (~37%) are out-of-bag. Each tree is scored on its OOB rows, which gives a validation estimate without a separate validation set.

6.3Random Forest and Extra Trees

Random Forest = bagging of trees + a random subset of features at each split. Trees become less correlated, so averaging them reduces variance more. Scikit-Learn predicts the class with the highest average probability across trees.

6.4Feature importance

  • = mean decrease in impurity: how much each feature reduced impurity across all the trees.
  • Useful for interpretation and feature selection, but it shows association, not causation.
  • Correlated features share importance: perimeter, area and radius all measure size, so the credit is split between them.

6.5Boosting: AdaBoost and Gradient Boosting

Learners are trained sequentially; each new one fixes the mistakes of the ones before. Turns weak learners into a strong one, mainly reduces bias, and cannot be fully parallelized.

6.6Stacking

Voting uses a fixed rule; stacking learns how much to trust each base model. Its training data are cross-validated predictions, which reduces information leakage. It is more complex and expensive.

6.7The final comparison (Module 6 demo, 143 test patients)

  • The differences are small (2 to 8 errors out of 143), so confirm with cross-validation.
  • A simple, scaled logistic regression won: this data is almost linearly separable, so extra flexibility didn't help.
  • The Random Forest's 4 errors in the top row are malignant tumours predicted benign: the most dangerous error in screening. Check recall, not only accuracy.

Overall: ensembles trade simplicity and interpretability for accuracy and robustness.

Exam traps.
  • Bagging = independent / parallel / variance. Boosting = sequential / bias.
  • Random Forest = bagging + random features. Extra Trees = also random thresholds, no bootstrap by default.
  • OOB ≈ 37% of rows, an estimate without a validation set (NaN when there is no bootstrap).
  • Feature importance is not causation; correlated features share it.
  • Ensembles are not always better than a simple model.

Check yourself

Why might a single tree be sensitive to changes in the training data?

It has high variance: a small change can change the first splits, and every split below them changes too.

What extra randomness does a Random Forest introduce compared with bagging?

A random subset of features at each split.

Medical screening: which is more serious, malignant predicted as benign or the reverse?

Malignant predicted as benign (a false negative): a cancer goes untreated. So look at recall too, not only accuracy.

Say these out loud before the exam

What is the first step of any ML project, and what are the 9 steps?

Problem Definition: the business problem and objectives with stakeholders, the task type (classification/regression) and the performance measure that matches the cost of errors. Then Data Collection → EDA → Data Preparation → Feature Engineering → Model Training → Model Evaluation → Hyperparameter Tuning → Deployment & Monitoring, iterating with feedback and new data.

What is data leakage and how do you prevent it?

Information from the test set or the future reaching training, which makes scores too optimistic. Split first, fit preprocessing on training data only inside a Pipeline, tune with CV, and test once.

Why cross-validation instead of one split?

One split can be lucky or unlucky. k-fold trains and validates k times, so the mean is more reliable and the std shows stability.

Why is accuracy misleading on imbalanced data?

Always predicting the majority class already scores high (94% with 6% positives) while finding no positives. Use recall, precision, F1 and the confusion matrix.

What happens when you lower the decision threshold?

More cases are predicted positive: recall rises, precision usually falls. Use it when missing a positive is costly, and choose the threshold on validation data.

How does gradient descent work, and what does the learning rate do?

It starts from random parameters and repeatedly steps opposite to the gradient of the cost (MSE) to reduce it. The learning rate is the step size: too small is slow, too large overshoots and diverges.

How do you detect overfitting with learning curves, and how do you fix it?

Training error is low and validation error much higher (a gap). Fix it with regularization (Ridge/Lasso, max_depth), a simpler model, early stopping or more data.

How does CART build a tree?

Greedily: at each node it tries features and thresholds, keeps the split with the largest impurity reduction (Gini or entropy), and repeats on each child until a stopping rule.

Why is a Random Forest better than one tree?

One tree has high variance. A forest trains many trees on bootstrap samples with random features per split, so they are diverse and their averaged vote has lower variance and generalizes better. OOB gives a built-in estimate.

Bagging vs boosting in one breath?

Bagging trains independent models in parallel on bootstrap samples and mainly reduces variance. Boosting trains models one after another, each fixing the previous errors, and mainly reduces bias.

Does high feature importance prove causation?

No. It shows the model relies on the feature (association). Confounders and correlated features can explain it, and correlated features share importance.

When would you choose a simple tree or logistic regression over an ensemble?

When decisions must be explained (healthcare, finance), when the accuracy gain is small or not confirmed by CV, or when the data are nearly linear, as in the breast-cancer demo where logistic regression won.
